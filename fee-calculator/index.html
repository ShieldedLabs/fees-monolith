Zcash Dynamic Fees

Zcash now publishes a fee suggestion with two tiers: a standard fee and a priority fee for faster inclusion. The obvious privacy question is how much the choice reveals. This page measures it directly from mainnet: how many real transactions take priority, and how that splits the anonymity set. The specs and the design are linked throughout.

How the number is made

A suggestion from public data, nothing more

The estimator reads only already-public data: confirmed blocks, never the mempool. It is an algorithmic posted-price estimator with a discrete fee alphabet, not a continuous-bid auction. Each step maps to a property worth keeping.

How this rolls out

Permissionless and incremental: it ships as wallet conventions and a fee suggestion, no network upgrade required. The streamlined Shielded Labs roadmap is three phases.

1

Experimental wallet pilots

in progress

Wallet partners add three opt-in features: a Priority switch, a short transaction expiry, and a speed-up button that resubmits an expired transaction at the priority rate. The point is to watch real adoption, not to gate anything.

↓
2

The fee estimator (z_getstandardfee)

in progress

A full node computes the standard and priority fees from confirmed blocks, and indexers relay them so every wallet quotes the same number. The live readings above come from it.

↓
3

Parameter tuning

future

Lower ZIP-317's marginal fee (5,000 → 1,000) once behavior data supports it. Today's 4× priority and 5,000 floor are the interim; a wider 10× lane is a possible later refinement.

Two ZIPs back this: one for the estimator, one for the parameter changes, both on the specs page.
